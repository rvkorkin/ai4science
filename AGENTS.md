# AGENTS.md — контракт для агента при работе над статьёй

Курс ШАД «ИИ-ассистенты для исследователя. AI4Science», неделя 10.
Статья: «Ранее обнаружение frac-hit по LF-DAS: клин, каузальность, soft-labels».

> Агент (Goose/Cursor) **читает этот файл в начале каждого сеанса**.
> Всё, что должно пережить сеанс, — здесь и в git.

---

## 1. Что считается готовым (definition of done)

Статья готова к сдаче, когда:
1. **Фактура сверена.** Каждая цифра/утверждение в тексте имеет источник: ссылка на статью (DOI/arXiv) **или** артефакт из `checks/results/`. Фальсификатов (выдуманных DOI, чисел «из головы») — ноль.
2. **Структура.** Есть все обязательные разделы (см. `openspec/REQUIREMENTS.md`): аннотация, введение, литобзор, методология (данные + предобработка + модель), **проверка** (переезжает из ДЗ-2), результаты, ограничения, заключение, ≤10 источников.
3. **Длина.** 2–4 страницы A4 тезисов (не полная статья).
4. **Каркас.** `ONTOLOGY.yaml` и `GLOSSARY.md` согласованы с текстом (каждый термин статьи — в глоссарии, каждая сущность — в онтологии).
5. **Проверка.** `pytest -q checks` зелёный на свежем клоне.
6. **Авторство размечено:** inline `[написано]/[порождено: модель]/[источник: …]` + таблица в конце.

## 2. Что запрещено

- **Фабриковать DOI, цифры, цитаты.** Если факт нужен — ищем источник (`web_search` / `pdf_search` по локальному graph_rag) или прогоняем эксперимент.
- **Переписывать `hw2` / ДЗ-2.** ДЗ-2 заморожена; оттуда только **читаем** и копируем `checks/`.
- **Рефакторить `src/preprocess.py` или `src/wedge_near.py`.** Это production-код проекта — по ссылке в статье, не модифицируем.
- **Коммитить закрытые данные** (`*.npz` полевые, `.env`, ключи).
- **Менять `ONTOLOGY.yaml` / `GLOSSARY.md`** в одиночку без синхронизации с текстом (сначала правка файла → потом текст, или наоборот, но не расхождение).

## 3. Рабочий процесс сеанса

1. Прочитать `AGENTS.md` (этот файл), `STATUS.md` (где мы), `diary.md` (последние 1–2 записи).
2. Проверить `openspec/REQUIREMENTS.md` на предмет актуальной задачи сеанса.
3. Сделать работу. Любые решения/тупики — писать в `diary.md`.
4. В конце сеанса: обновить `STATUS.md`, добавить запись в `diary.md`, коммит с осмысленным сообщением.
