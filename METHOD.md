# METHOD.md — методика проверки (ДЗ-2 «Проверка»)

Курс ШАД «ИИ-ассистенты для исследователя. AI4Science». Шаблон недели 6.
Методика записана **до** финального прогона эксперимента (см. `git log --reverse`).

## 1. Замысел

Проект — раннее предсказание frac-hit по LF-DAS strain-rate (TrafficLight, модель
SeqCNNGRU). Научная корректность всех метрик модели держится на одном инварианте:
**предобработка каузальна** — выход в момент `i` зависит только от входа до реального
времени `i·R`. Нарушение (look-ahead-утечка в per-file нормализации) в своё время
отправило в отставку CNN-per-crop (см. `core/WORKLOG.md` проекта): метрики были
недостоверно завышены. Проверяем именно этот кусок.

## 2. Постановка эксперимента

- **Что фиксируется:** данные (один и тот же seed → одни и те же последовательности
  для обоих конвейеров), модель (logistic regression), сплит train/test (70/30),
  раннее окно `[5,20]` (заведомо ДО онсета хита `[40,80]`).
- **Что меняется (единственный фактор):** способ нормировки признаков раннего окна —
  **causal** (статистики только прошлого) против **leaky** (статистики всей
  последовательности, включая будущее после онсета).
- **Что измеряется:** AUC и AP детекции хита по раннему окну; первичная метрика — AUC.
- **Повторы:** 5 seed (0–4), сравнение **парное** по seed.

## 3. Данные и их версия

- **Верификатор свойств/данных:** полевые npz `field_data_enriched/*.npz`
  (626 записей, ревизия корпуса на 2026-11-05), лейблы `core/field_strongest_hits.json`,
  `core/split.json`. Данные под закрытой лицензией — **вне репозитория** (политика как в
  ДЗ-1); верификатор ссылается на них через `FIELD_DATA_DIR`/`TL_CORE`, а результаты
  прогона приложены в `checks/results/`.
- **Численный эксперимент (K4):** полностью **синтетические** DAS-подобные данные,
  генерируются детерминированно от seed внутри `checks/experiment.py` — проверяющему
  не нужны закрытые данные, эксперимент воспроизводится у него один-в-один.

## 4. Договор о схеме npz (валидатор данных)

| Поле | Тип/форма | Правило |
|---|---|---|
| `strain` | float (T, D) | конечные значения; T≥2, D≥1 |
| `strain_rate` | float (T, D) | та же форма, что `strain`; конечные |
| `depth` | float (D,) | монотонна; шаг dz ∈ [0.3, 6] м (иначе warning) |
| `dt_sec` | скаляр | `> 0` |
| лейбл `tpk` | int | для hit-файла `0 ≤ tpk < T` |
| split | — | `train ∩ val = ∅` по стемам; каждый стем имеет лейбл |

## 5. Правило принятия (записано ДО прогона)

Численный эксперимент заключает, что look-ahead-утечка **материально завышает** метрику,
только если ОДНОВРЕМЕННО выполнены три условия:

1. **Интервал.** 95%-доверительный интервал парной разности `Δ = AUC_leaky − AUC_causal`
   (парный t по 5 seed) **не содержит 0**.
2. **Практический порог.** `|Δ| > δ`, где `δ = 0.05` (полбалла детекции) — заранее
   выбранный порог практической значимости.
3. **Значимость с поправкой.** Парный t-критерий значим (`p < 0.05`) **после поправки
   Холма** по набору метрик `{AUC, AP}`.

Сравнение парное (общий seed → общие данные), поэтому сравниваются конвейеры, а не
реализации шума. Размер эффекта — Cohen `d_z`.

Для **верификатора свойств/данных** правило бинарное (hard-fail): есть хоть одно
нарушение инварианта (утечка будущего в выход, пересечение стемов train/val, `tpk` вне
`[0,T)`, NaN/inf, `dt_sec≤0`) → вердикт «не принято».

## 7. Ограничения методики

- Property-тесты покрывают чистые функции `src/preprocess.py`; причинность GRU-warmup
  в `nn_seq_pipeline` здесь не тестируется.
- K4-эксперимент синтетический: он показывает **механизм и цену** утечки, а не
  абсолютные числа production-модели (честные pairloo-OOF AUC проекта — отдельно).
- Валидатор проверяет схему и физику, но не корректность самих ручных меток хита.
