# Фрагмент сеанса агента: вызов инструмента по описанию

Модель: `claude-opus-4-8-thinking-low` через харнесс AI4Science. Инструмент
`frac_hit_verify` подключён MCP-сервером `frac-hit` (`mcp/frac_hit_mcp.py`),
имя инструмента в запросе не названо.

Запрос пользователя (дословно, без имени инструмента):

> У меня есть файл `scenario/fixtures/rec_hit.npz` --- одна запись LF-DAS из
> нашего проекта. Мне нужно для раздела «Результаты» вставить одну строку
> вида «инструмент оценил время прихода frac-hit на записи такой-то в X мин».
> Прежде чем я поверю числу из своей головы, проверь файл и дай мне то
> число, которое получает наш проверенный код проекта.

Строка вызова из сеанса и ответ:

```
▸ frac_hit_verify frac-hit
{"file": "rec_hit.npz", "valid": true, "errors": [], "warnings": [],
 "stats": {"T": 120, "D": 40, "dt_sec": 60.0},
 "hit": {"estimated": true, "hit_time_min": 92.11,
         "closest_approach_idx": 90, "n_converging_steps": 37}}
```

Ответ модели пользователю:

> Файл прошёл проверку схемы и физических инвариантов. Инструмент оценил
> время прихода frac-hit в $92{,}11$ мин для `rec_hit.npz` (сходящихся
> шагов~37).

## Что пришлось править в строке документации

Первая версия docstring начиналась с описания механики инструмента
(«валидирует схему и считает кинематику клина...»). Модель её **не
вызывала**: при похожем запросе предпочитала писать число сама. После того
как первым абзацем docstring стало прямое «Вызывать, когда модель пишет про
результат на конкретной записи LF-DAS и должна сверить число минут до
прихода с проверенным кодом проекта, а не со своей памятью» --- инструмент
начал вызываться сразу (см. `mcp/frac_hit_mcp.py`, строки 50--68).
